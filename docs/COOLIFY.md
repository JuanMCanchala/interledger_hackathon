# Deploying to Coolify

One Coolify resource runs the whole stack from `docker-compose.coolify.yml`: PostgreSQL, the
backend and the frontend. Only the frontend gets a domain: its nginx serves the Angular app and
proxies `/api` to the backend over the internal network, so the app lives under a single URL.

## Create the resource

1. **+ New → Public Repository**, URL `https://github.com/JuanMCanchala/interledger_hackathon`.
2. Branch: `prod` (the team promotes `dev` → `qa` → `prod`). Build Pack: **Docker Compose**.
   Base directory `/`, Docker Compose location `/docker-compose.coolify.yml`.
3. On the **frontend** service, set the domain with the container port:
   `https://miplante.example.com:3001` (or the generated `sslip.io` one for a quick test).
   Leave `backend` and `db` without a domain.

## Environment variables

| Variable                   | Value                                                              |
| -------------------------- | ------------------------------------------------------------------ |
| `PUBLIC_BASE_URL`          | The frontend's public URL, no trailing slash                       |
| `OP_CLIENT_WALLET_ADDRESS` | The app's wallet address, e.g. `$ilp.interledger-test.dev/my-shop` |
| `OP_KEY_ID`                | Key ID from the test wallet (Settings → Developer Keys)            |
| `OP_PRIVATE_KEY`           | `private.key` in base64: `base64 -w0 private.key`                  |

Optional: `OP_ALLOWED_WALLET_HOSTS`, `OP_WALLET_SEND_URL`, `OP_LOG_LEVEL` (defaults as in
`env.example`), and `DEEPSEEK_API_KEY` (with `DEEPSEEK_MODEL`) for GlorIA's answers: without the
key she still understands charge and navigation requests on the device (ADR 0017). The database user and password are generated by Coolify
(`SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES`); the backend applies pending migrations
every time it starts.

Use HTTPS: the PWA service worker and the camera for the QR need a secure origin, and the wallet
returns the user to `PUBLIC_BASE_URL` after consent. Changing the domain means updating
`PUBLIC_BASE_URL` and redeploying.
